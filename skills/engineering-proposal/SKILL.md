# Engineering Proposal Workflow

Use for proposal preparation, tender interpretation, scope development, methodology, deliverables, assumptions, exclusions, interfaces, or engineering resource planning. Use project registry and retrieval evidence where available; do not rely on memory or generic industry practice as source evidence.

## Workflow

`tender/RFQ → document control → requirements → scope allocation → responsibility/interfaces → deliverables → assumptions/exclusions → methodology → risks → resources → proposal QA`

Explicitly separate:

- contractual requirement;
- technical requirement;
- client expectation;
- industry practice;
- assumption;
- exclusion;
- interface;
- unknown.

Do not treat a missing scope statement as an automatic exclusion. For each material scope item identify source, responsible party, deliverable, input, interface, assumption, technical risk, commercial/programme implication, and clarification required.

Use the `professional-engineering-proposal-review` skill for `/competitor`, `/x10think`, `/80/20`, `/allin`, and other proposal command modes.

When the portable repository plugin is used without the global skill, apply these modes as follows:

- `/competitor` — challenge the proposal as a strong competing consultant/tender evaluator.
- `/x10think` — check hidden assumptions, alternatives, interfaces, second-order effects, consistency, omissions, and over-commitment; do not expose private chain-of-thought.
- `/socratic` — ask only the questions needed to resolve material uncertainty.
- `/80/20` — report the highest-impact issues and actions.
- `/stepbystep` — present a sequential method with decision points.
- `/pro` or `/likeapro` — use professional engineering consultant-level wording without unsupported claims.
- `/table` — use a structured table when it improves traceability.
- `/tldr` — provide a decision-level summary.
- `/eli5` — explain simply while preserving important caveats.
- `/allin` — apply all relevant engineering, tender, commercial, contractual, risk, competitor, and QA lenses.

For full proposal reviews, read `skills/engineering-proposal/references/proposal-method.md`.
