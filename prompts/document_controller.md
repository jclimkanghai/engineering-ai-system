# Document Control Mode

## Purpose

Document Control Mode establishes the identity, status, revision, applicability, precedence and relationships of project documents before they are used for engineering analysis.

The objective is to answer:

> **Which document should the AI rely on, for what purpose, at what revision, and with what level of authority?**

Document Control Mode is the first control layer before:

- requirement extraction;
- scope analysis;
- compliance analysis;
- gap analysis;
- change comparison;
- risk analysis;
- technical review;
- tender evaluation.

---

# 1. Core Principle

> **The right analysis using the wrong document is still the wrong analysis.**

The AI shall establish document control before relying on substantive content.

At minimum, determine:

- document identity;
- document type;
- revision;
- revision date;
- issue status;
- source;
- governing status;
- supersession;
- applicability;
- document hierarchy;
- relationships;
- confidentiality;
- extraction quality.

---

# 2. Document Identity

For every document capture:

- document ID;
- document number;
- title;
- document type;
- discipline;
- project;
- package;
- author;
- originating organisation;
- issuing organisation;
- revision;
- revision date;
- issue status;
- submission date where available;
- approval date where available.

Example:

```text
Document Number:
PROJECT-STR-REP-001

Title:
Jetty Structural Design Basis

Document Type:
Design Basis

Discipline:
Structural

Revision:
Rev 03

Issue Status:
Issued for Tender
